## Scope

Implement a detection mechanism to check if a delegated model (e.g., via OpenRouter or LM Studio) lacks coding capabilities. If detected, automatically inject a message/comment in the resulting PR explaining that the project stalled because the model lacks coding ability. The message must explicitly suggest capable alternative models (e.g., in LM Studio, OpenRouter, or keyless Perplexity). Ensure every WR generates a PR by default. Out of scope: automatically switching models mid-run (we only report the error and suggest alternatives).

## Approach

Add a validation step in the relevant agent/PR generation workflows to verify the chosen model against a known "no-code" list or by checking a capability flag. If validation fails, use `github-script` or the GitHub API to post a comment on the PR indicating the failure reason. The step should then fail the CI job explicitly so the user knows intervention is required. This ensures a clear signal instead of a silent failure.

## Acceptance Criteria

- [ ] Change delivers the described behavior end-to-end
- [ ] PR message is injected when a non-coding model is attached
- [ ] Alternative models are suggested correctly in the message
- [ ] Tests updated / added where applicable
- [ ] Docs updated where applicable
- [ ] No regressions in related workflows

## Risks & Mitigations

- **Risk:** Hardcoded model lists get outdated.
  **Mitigation:** Use a dynamic check, easily configurable list, or pull from a centralized model registry.
- **Risk:** Comment loop (posting the same comment multiple times).
  **Mitigation:** Check for existing comments from the bot before posting, or ensure the comment is only posted once per failed run.

Bounding the scope to clearly communicate LLM capability mismatches prevents confusing silent failures and saves developer debugging time by explicitly suggesting capable alternatives like keyless Perplexity.
