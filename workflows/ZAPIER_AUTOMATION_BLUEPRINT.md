# Zapier Automation Blueprint

This blueprint provides the exact Zap setup for automated social media scheduling and publishing via Webhooks by Zapier to platforms like Buffer or Hootsuite.

## Trigger Setup

1. **App Event:** Webhooks by Zapier
2. **Trigger Event:** Catch Hook
3. **Webhook URL:** The URL generated by Zapier (paste this into GitHub Secrets as `ZAPIER_WEBHOOK_URL`).

## Action 1: Filter (Safeguard)

1. **App Event:** Filter by Zapier
2. **Condition:** Only continue if...
3. **Field:** Header `X-GitHub-Event` exists (or filter by specific payload fields if needed to distinguish between live and test payloads).
4. **Purpose:** Ensures that only genuine payloads from merged PRs proceed to the publishing steps, preventing accidental live posts during testing.

## Action 2: Delay/Schedule Logic (Optional)

1. **App Event:** Delay by Zapier
2. **Action Event:** Delay For (e.g., 2 hours) or Delay Until (specific time).
3. **Purpose:** Staggers posts or aligns them with optimal engagement times.

## Action 3: Social Media Publish (e.g., Buffer)

1. **App Event:** Buffer
2. **Action Event:** Add to Queue (or Create Post)
3. **Account:** Connect your Buffer account.
4. **Field Mapping:**
   - **Text:** Map the formatted text from the webhook payload (e.g., `twitter`, `linkedin`, `facebook`).
   - **Profile:** Select the corresponding profile for the mapped platform.

## Testing Flow & Validation

- **Local Unit Tests:** Write simple bash/Node scripts locally to verify payload formatting.
- **GitHub Actions Dry-Run:** Create a mock PR to trigger the Action and view the payload structure in the Action logs without an active webhook URL (or by sending to a temporary request bin).
- **Zapier Webhook Test:** Send sample JSON to the Zapier Catch Hook URL to verify field extraction and filter passing.
- **Publish Readiness Checklist:**
  - [ ] Action fires only on merged PRs.
  - [ ] Webhook URL is stored securely in GitHub Secrets.
  - [ ] Payload correctly maps to Zapier fields.
  - [ ] Zapier filter correctly distinguishes test vs. live payloads (if configured).
  - [ ] Posts are queued or published successfully without immediate live posting during tests.
