## 1. Purpose

Define an **Autonomous BNAT** (Best-Next-Available-Thing) **Invention Loop** in which agents:

1. **Scan** for opportunity gaps,
2. **Invent** candidate solutions,
3. **Screen** them under DOE-5 kill discipline,
4. **Decide** using the WR-4483 ensemble (AHP + RICE),
5. **Build** M1 (Milestone-1) skeletons, and
6. **Draft** IP / disclosure artifacts.

All of the above happens **without a human in the inner loop**, but **no launch, no listing, and no filing** occurs without an explicit **human merge gate**.

This standard is aligned with the PRIME DIRECTIVE ($10k/mo → $10M in 3 yrs) as a **top-of-funnel invention pipeline** feeding Polar.sh products, OSINT tools, and the automated product pipeline.

---

## 2. Hard constraints (non-negotiable)

These constraints are load-bearing. Any PR that weakens them must be rejected.

1. **Human merge gate.** No agent may:
   - launch a product,
   - list a product on any marketplace (Polar.sh, Stripe, GitHub Sponsors, App Store, etc.),
   - file any IP artifact (provisional, non-provisional, PCT, trademark, copyright registration),
   - or publish a public disclosure,

   without a **human-approved merge** of the corresponding PR. Agents **draft**; humans **decide and file**.

2. **Legal reality — inventorship and authorship.**
   - Under **Thaler v. Vidal**, 43 F.4th 1207 (Fed. Cir. 2022), an AI system **cannot be a named inventor** on a US patent. A natural person must be the inventor of record.
   - Under **US Copyright Office guidance (2023)** ("Copyright Registration Guidance: Works Containing Material Generated by Artificial Intelligence," 88 Fed. Reg. 16190), works lacking human authorship are not registrable; only the human-authored portions are protected.
   - Therefore: **agents draft, humans are inventor/author of record.** Agent contributions are logged as **tooling**, not authorship.

3. **DOE-5 kill discipline.** The Design-of-Experiments screening stage must **kill** candidates that fail pre-registered criteria. **A 0% kill rate is a red flag**, not a success. Target kill rate: **≥ 40%** at DOE-5, tracked as a KPI.

4. **Calibration, not approval, is the target metric.** The loop is scored by **Brier score < 0.20** on agent forecasts vs. realized outcomes — **not** by "approval rate" or "volume of PRs merged." Optimizing for merge count is explicitly out of scope.

5. **Little's Law WIP cap.** By Little's Law (`L = λ·W`), throughput is capped by WIP. The loop enforces a **hard WIP cap** (default: 5 active BNAT candidates in-flight per agent pool) to keep cycle time `W` bounded.

6. **Named-math citations required.** Every stage output must cite the named method it invokes (see §4). Un-cited outputs are rejected at review.

## 4. Stages

Each stage cites the named math it uses. Outputs are structured artifacts committed to `wr/bnat/<candidate-id>/`.

### Stage 1 — SCAN (opportunity gaps)

- **Method:** **Ulwick Opportunity Score** = `Importance + max(0, Importance − Satisfaction)` (Anthony Ulwick, *What Customers Want*, 2005).
- **Input:** JTBD (Jobs-To-Be-Done) survey signal, GitHub issue mining, Polar.sh funding signals, OSINT trend feeds.
- **Output:** `scan.json` — ranked list of gaps with Opportunity Scores. Only gaps with score **≥ 12** advance.

### Stage 2 — INVENT (candidate generation)

- **Method:** **TRIZ** (Altshuller, *Creativity as an Exact Science*, 1984) — 40 inventive principles applied to the top-ranked contradictions from Stage 1.
- **Output:** `invent.json` — ≥ 3 candidate solutions per gap, each tagged with the TRIZ principle(s) invoked.

### Stage 3 — SCREEN (DOE-5 kill discipline)

- **Method:** **Design of Experiments**, 5-factor screening (Fisher, *The Design of Experiments*, 1935; Box, Hunter & Hunter, *Statistics for Experimenters*, 2005). Pre-registered kill criteria on 5 factors:
  1. Technical feasibility (binary)
  2. Legal feasibility (binary — patent freedom-to-operate rough check)
  3. Market size ≥ $1M TAM (binary)
  4. Time-to-M1 ≤ 30 days (binary)
  5. Cost-to-M1 ≤ $500 (binary)
- **Rule:** Any candidate failing ≥ 1 factor is **killed**. Target kill rate ≥ 40%.
- **Output:** `screen.json` with kill/pass verdict and factor scores.

### Stage 4 — DECIDE (WR-4483 ensemble)

- **Method:** **AHP** (Saaty, *The Analytic Hierarchy Process*, 1980) for weighted multi-criteria ranking, combined with **RICE** (Reach × Impact × Confidence / Effort; Intercom, 2016) for prioritization. Ensembled per WR-4483.
- **Calibration:** Agent confidence values are tracked against outcomes; **Brier score** (Brier, 1950) must stay `< 0.20` on a rolling 20-candidate window.
- **Output:** `decide.json` — ranked survivor list with AHP weights, RICE scores, and confidence intervals.

### Stage 5 — BUILD (M1 skeleton)

- **Method:** Minimum viable skeleton — repo scaffold, CI, one end-to-end happy path, one automated test. No production traffic.
- **WIP cap:** Little's Law — no more than 5 M1 skeletons in-flight per agent pool.
- **Output:** PR to a `bnat/<candidate-id>` branch with `M1.md` build log.

### Stage 6 — DRAFT IP (disclosure artifacts)

- **Method:** Agent drafts:
  - invention disclosure form (IDF),
  - prior-art search summary,
  - claim scaffold (independent + 3 dependent),
  - trademark / copyright candidate list.
- **Legal:** Draft is marked `HUMAN-INVENTOR-OF-RECORD: <name>` per Thaler v. Vidal. Agent contributions logged under `TOOLING:` line.
- **Output:** `ip-draft.md` in the candidate directory. **Never filed by an agent.**

### Stage 7 — GATE (HUMAN MERGE REQUIRED)

This is the hard stop.

**Nothing downstream of Stage 6 happens without a human merge.** Specifically:

- Product launch → requires human merge of a `launch/*` PR.
- Marketplace listing (Polar.sh, Stripe, etc.) → requires human merge of a `list/*` PR.
- IP filing → requires a human, as inventor/author of record, to sign and file. The repository merely stores drafts.
- Public disclosure (blog, tweet, README push to a public repo) → requires human merge.

The GATE PR checklist:

- [ ] Stage 1–6 artifacts present and cite named math.
- [ ] DOE-5 kill rate for the current window ≥ 40%.
- [ ] Rolling Brier score < 0.20.
- [ ] WIP ≤ 5.
- [ ] Human inventor/author of record named.
- [ ] Reviewer has read this file (WR-4484) end-to-end.

A GATE PR that fails any checkbox **must not be merged**.

## 6. Alignment with PRIME DIRECTIVE

This loop feeds the four-phase revenue plan:

- **Phase 1 ($10k/mo):** Loop targets Polar.sh-fundable micro-tools and OSINT utilities with time-to-M1 ≤ 30 days.
- **Phase 2 ($30k/mo):** Loop widens to bundled offerings; RICE `Reach` weight increases.
- **Phase 3 ($100k/mo):** Loop feeds automated product pipeline; IP drafts begin to matter as moats.
- **Phase 4 ($10M total):** Filed IP (by human inventors of record) becomes a balance-sheet asset.

At every phase, the **human merge gate remains**. Scaling the loop means scaling *invention throughput*, not autonomy over launches or filings.
