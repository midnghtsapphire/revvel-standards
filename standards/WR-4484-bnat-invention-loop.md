# WR-4484 — Autonomous BNAT Invention Loop (human-gated)

**Status:** rev-0
**Band:** 44xx (Autonomy / Invention)
**Register:** wr-register
**Depends on:** WR-4483 (ensemble AHP + RICE decision framework)
**Autonomy directive:** 🛑 **HUMAN MERGE REQUIRED** — Agents draft, screen, and recommend. Humans decide, sign, and file.

---

## 1. Purpose

Define a repeatable, auditable loop by which autonomous agents:

1. **Scan** for unmet needs and technical gaps (BNAT = Best Not Available Today).
2. **Invent** candidate solutions.
3. **Screen** them with DOE-5 kill discipline.
4. **Decide** using the WR-4483 ensemble (AHP + RICE).
5. **Build** M1 (milestone-1) skeletons — code, spec, or bench artifacts.
6. **Draft** IP artifacts (invention disclosures, prior-art maps, claim scaffolds).

A **hard human-merge gate** blocks any external action: launch, listing, filing, publication, or customer contact.

The loop's KPI is **calibration** (Brier score), not throughput or approval rate.

---

## 2. Hard constraints (do not violate)

These are **non-negotiable**. Any agent, workflow, or downstream WR that violates them is out of spec.

| # | Constraint | Legal / methodological basis |
|---|---|---|
| H1 | **No agent may be listed as inventor or author of record.** | *Thaler v. Vidal*, 43 F.4th 1207 (Fed. Cir. 2022); USCO *Copyright Registration Guidance: Works Containing Material Generated by Artificial Intelligence* (March 16, 2023). |
| H2 | **No agent may file with USPTO, EPO, WIPO, or any registry.** | Filings require a natural-person inventor and attorney/agent of record. |
| H3 | **No agent may publish, list, launch, or contact customers.** | External surface = human-gated. |
| H4 | **Every recommendation must cite the math it used** (Ulwick, TRIZ, DOE-5, RICE, AHP, Brier, Little's Law). | Auditability. No black-box recommendations. |
| H5 | **Kill rate must be tracked and reported.** A 0% kill rate over any 10-candidate window is a **red flag** and pauses the loop for human review. | DOE-5 kill discipline is the whole point of screening. |
| H6 | **Brier score target: < 0.20** on a rolling 30-decision window. If Brier ≥ 0.20, downgrade agent recommendations to advisory-only until recalibrated. | Calibration is the KPI, not approval rate. |
| H7 | **WIP cap** (Little's Law): concurrent live candidates ≤ ⌊throughput_target × cycle_time⌋. Exceeding cap blocks new SCAN outputs. | Prevents queue explosion. |
| H8 | **All artifacts are drafts** until a human merges the PR that promotes them. | Merge = human signature of record. |

## 3. Stages

### 3.1 SCAN — gap detection

**Inputs:** market signals, issue tracker, competitor telemetry, patent-drop feeds, user interviews (transcribed).

**Method:**
- **Ulwick Opportunity Score** = Importance + max(Importance − Satisfaction, 0), on a 1–10 scale per outcome statement.
- Threshold: OS ≥ 12 → candidate gap.
- **TRIZ contradiction matrix** applied to each gap to surface inventive principles.

**Output:** `gaps/<yyyy-mm-dd>-<slug>.md` with:
- Outcome statement (JTBD format)
- OS score with I and S values
- TRIZ contradictions identified (if any)
- Prior-art quick-look (≤ 5 references)

**Kill rule:** OS < 12 → drop, log, done.

---

### 3.2 INVENT — candidate generation

**Inputs:** SCAN output.

**Method:**
- Generate **≥ 5 distinct candidate solutions** per gap (diversity requirement).
- Each candidate must map to at least one TRIZ inventive principle.
- Each candidate must state its **falsifiable hypothesis** (what would prove it wrong).

**Output:** `candidates/<gap-slug>/<candidate-id>.md`.

**Kill rule:** < 5 distinct candidates → SCAN was too narrow; re-scan.

---

### 3.3 SCREEN — DOE-5 kill discipline

**Inputs:** candidate set.

**Method:** apply five kill filters. **Failing any one kills the candidate.**

| Filter | Question | Kill threshold |
|---|---|---|
| D1 Desirability | Does OS ≥ 12 hold when re-scored against this candidate specifically? | No → kill |
| D2 Feasibility | Can M1 be built in ≤ 2 weeks with existing stack? | No → kill |
| D3 Viability | Does RICE (WR-4483) return score ≥ 20? | No → kill |
| D4 Defensibility | Is there a plausible claim scaffold (novelty + non-obviousness)? | No → kill |
| D5 Ethics/Legal | Any H1–H3 or regulatory red flag? | Yes → kill |

**Output:** `screened/<gap-slug>/survivors.md` + kill log.

**Kill-rate KPI:** expected kill rate ≥ 60% over rolling 10-candidate window. 0% kill rate → **PAUSE LOOP**, escalate to human.

---

### 3.4 DECIDE — WR-4483 ensemble

**Inputs:** SCREEN survivors.

**Method:** invoke WR-4483 (AHP for criteria weighting + RICE for scoring) as an **ensemble** with ≥ 3 independent agent runs. Report:
- Mean and stdev of RICE scores
- AHP consistency ratio (CR); reject if CR > 0.10
- **Brier score** of each agent's past predictions (rolling 30)

**Output:** ranked recommendation list with confidence bands.

**Kill rule:** Brier ≥ 0.20 for the ensemble → recommendations are advisory-only.

---

### 3.5 BUILD (M1) — skeleton only

**Inputs:** top-ranked candidate(s) within WIP cap.

**Method:**
- Agents draft M1 skeleton: minimum code / spec / bench rig to test the falsifiable hypothesis from INVENT.
- No production wiring. No external endpoints. No customer data.
- All work on a feature branch, opened as a **draft PR**.

**Output:** draft PR + M1 test plan.

---

### 3.6 DRAFT-IP — invention disclosure artifacts

**Inputs:** BUILD M1 + SCREEN D4 claim scaffold.

**Method:** agents draft, humans own:
- Invention disclosure form (IDF) — **inventor field left blank for human to fill**
- Prior-art map (≤ 20 references, cited)
- Claim scaffold (independent + 3 dependents, marked DRAFT)
- Enablement notes

**Output:** `ip-drafts/<candidate-id>/` — all files stamped `DRAFT — NOT FOR FILING`.

**Constraint (H1, H2):** no agent name appears in any inventor, author, or filer field. Ever.

---

### 3.7 GATE — 🛑 HUMAN MERGE REQUIRED

**This stage cannot be automated. Read carefully.**

Before any of the following may occur, a human with commit rights must review and merge the promoting PR:

- Any external launch or beta invite
- Any product listing (Polar.sh, marketplace, store)
- Any IP filing (provisional, non-provisional, PCT, design, copyright)
- Any publication (blog, paper, preprint)
- Any customer contact tied to the candidate

**Human review checklist** (must appear in PR template):

- [ ] I have read the SCREEN kill log and agree with survivors.
- [ ] I have read the DECIDE ensemble output including Brier and CR.
- [ ] I confirm no H1–H8 constraint is violated.
- [ ] I am the named inventor / author / filer of record where applicable, or I have identified who is.
- [ ] Legal review is complete for filings, or explicitly deferred with rationale.
- [ ] I accept responsibility for the external action this merge enables.

Merge without all boxes checked is a process violation and must be logged in `governance/violations.log`.

## 4. Metrics (reported weekly)

| Metric | Target | Source |
|---|---|---|
| Brier score (rolling 30) | < 0.20 | DECIDE |
| Kill rate (rolling 10) | ≥ 60% | SCREEN |
| WIP (live candidates) | ≤ cap | Little's Law |
| Cycle time SCAN→GATE | ≤ 21 days | Loop telemetry |
| Human-gate violations | 0 | `governance/violations.log` |
| AHP consistency ratio | ≤ 0.10 | DECIDE |

**Do not report** approval rate as a headline metric. Approval rate without calibration is vanity.

---

## 5. Failure modes and responses

| Failure | Signal | Response |
|---|---|---|
| Agent drift into filing | Any PR touching filing systems | Auto-block, page human |
| Kill rate collapse | 0% over 10 | Pause loop, escalate |
| Calibration decay | Brier ≥ 0.20 | Downgrade to advisory, retrain |
| WIP overflow | Live > cap | Block SCAN output |
| Inventor-field auto-fill | Agent name in IDF | Reject artifact, log violation |
