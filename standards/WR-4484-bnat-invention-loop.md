# WR-4484 — Autonomous BNAT Invention Loop (Human-Gated)

**Status:** rev-0
**Band:** 44xx (Autonomy / Invention)
**Labels:** wr-register, band-44xx, rev-0
**Autonomy Directive:** 🛑 **HUMAN MERGE REQUIRED** — agents never file, list, or launch without a signed human merge.

---

## 1. Purpose

Define the **Autonomous BNAT (Big-New-And-Testable) Invention Loop**: a pipeline where agents scan for opportunity gaps, invent candidate solutions, screen them with hard kill discipline, decide via a WR-4483 ensemble (AHP + RICE), build M1 skeletons, and draft IP artifacts — with a **hard human-merge gate** before any external action (launch, listing, filing, or public disclosure).

This standard operationalizes the **Prime Directive** ($10k/mo → $10M in 3 years) by making invention throughput measurable, calibrated, and legally clean.

---

## 2. Hard Constraints (READ FIRST)

1. **Agents draft. Humans are inventor/author of record.**
   - Legal basis: *Thaler v. Vidal*, 43 F.4th 1207 (Fed. Cir. 2022) — an AI system cannot be a named inventor under 35 U.S.C. § 100(f).
   - USCO 2023 guidance (*Copyright Registration Guidance: Works Containing Material Generated by Artificial Intelligence*, 88 FR 16190) — human authorship is required; AI-generated portions must be disclosed and disclaimed.
2. **Agents never file.** No USPTO submission, no provisional, no trademark filing, no domain purchase, no product listing, no press release originates from an agent action. Filing is a human act by a named human inventor/attorney.
3. **Human merge gate is non-bypassable.** CI must block any PR that touches `launch/`, `filings/`, `listings/`, or `press/` unless it carries a signed `human-merge-approved` label from a repo maintainer (CODEOWNERS-enforced).
4. **Kill discipline is a KPI.** A 0% kill rate is a **red flag**, not a success. Target kill rate is 60–80% at DOE-5 screening.
5. **Calibration > approval rate.** The optimization target is **Brier score < 0.20** on agent confidence predictions, not the number of ideas advanced.

## 3. Pipeline Stages

Each stage cites the **named math / method** it uses. Deviations require a WR amendment.

### Stage 1 — SCAN (Gap Detection)
- **Method:** Ulwick **Opportunity Score** = Importance + max(0, Importance − Satisfaction), on a 1–10 scale per outcome statement (Ulwick, *What Customers Want*, 2005).
- **Input:** user forums, support tickets, competitor changelogs, GitHub issues, OSINT signals.
- **Output:** ranked list of unmet outcomes with Opportunity Score ≥ 12 (Ulwick's underserved threshold).
- **Agent role:** draft the outcome statements and score them.
- **Kill rule:** any outcome with score < 10 is dropped without further review.

### Stage 2 — INVENT (Candidate Generation)
- **Method:** **TRIZ** 40 Inventive Principles + contradiction matrix (Altshuller, *The Innovation Algorithm*, 1969/1999) applied to the top-N Opportunity Scores.
- **Output:** ≥ 5 candidate solutions per gap, each tagged with the TRIZ principle(s) invoked.
- **Agent role:** enumerate candidates and cite prior art (Google Patents, Semantic Scholar).
- **Anti-pattern:** "one obvious solution" — reject the batch and re-run with contradiction analysis.

### Stage 3 — SCREEN (DOE-5 Kill Discipline)
- **Method:** **Design of Experiments** with 5 pre-registered kill criteria (DOE-5). Each criterion is a falsifiable prediction with a threshold set **before** data collection.
- **The 5 kills:**
  1. **Market kill** — TAM < $1M/yr addressable → kill.
  2. **Tech kill** — feasibility probability < 0.4 (agent estimate, human-calibrated) → kill.
  3. **Legal kill** — blocking prior art or FTO risk flagged → kill.
  4. **Economics kill** — projected gross margin < 40% → kill.
  5. **Distribution kill** — no plausible CAC ≤ LTV/3 channel → kill.
- **Target kill rate:** 60–80%. Below 60% → screening is too soft. Above 80% → invention is too narrow.
- **Agent role:** run each candidate through the 5 kills and produce a screening report.

### Stage 4 — DECIDE (WR-4483 Ensemble: AHP + RICE)
- **Method:** ensemble of **Analytic Hierarchy Process** (Saaty, 1980) for pairwise-weighted multi-criteria, and **RICE** (Reach × Impact × Confidence ÷ Effort; Intercom, 2016) for throughput ranking. Per WR-4483, both must agree in the top quartile before advancement.
- **Calibration:** track agent Confidence values against realized outcomes; compute **Brier score** (Brier, 1950). Target < 0.20.
- **Agent role:** produce AHP matrix + RICE scorecard; flag disagreements between the two.

### Stage 5 — BUILD M1 (Skeleton)
- **Output:** minimal working artifact (M1 = Milestone 1 skeleton): README, one runnable script or endpoint, one test, one measurable outcome.
- **WIP cap:** per **Little's Law** (L = λW), cap concurrent M1s at ⌈λ · target-lead-time⌉. Default: **max 3 concurrent M1s per agent**.
- **Agent role:** scaffold M1; human reviews code before merge.

### Stage 6 — DRAFT IP (Provisional / Copyright / Trademark Drafts)
- **Output:** draft provisional patent spec, draft copyright notice, draft trademark description. All stored under `drafts/ip/` — **never** under `filings/`.
- **Disclosure:** every draft includes the required USCO AI-disclosure boilerplate identifying AI-generated portions.
- **Agent role:** produce drafts. **Human role:** review, edit, take inventorship, and file.

### Stage 7 — GATE (🛑 HUMAN MERGE REQUIRED)
- **Rule:** no artifact leaves the repo (no launch, no listing, no filing, no press) without:
  1. A PR reviewed by a human CODEOWNER.
  2. The `human-merge-approved` label applied by that CODEOWNER (not the PR author).
  3. A signed commit from the human on the merge.
- **CI enforcement:** `.github/workflows/human-gate.yml` (to be added in a follow-up WR) blocks merges to `main` on paths `launch/**`, `filings/**`, `listings/**`, `press/**` without the label.
- **Bypass:** none. An agent that attempts to self-approve triggers a WR-4484 violation and is quarantined.

## 4. KPIs

| KPI | Target | Red-flag |
|---|---|---|
| Kill rate at DOE-5 | 60–80% | <60% or >80% |
| Brier score (agent confidence) | < 0.20 | > 0.25 |
| M1 lead time | ≤ 7 days | > 14 days |
| Concurrent M1s per agent | ≤ 3 | > 3 (Little's Law violation) |
| Human-gate bypass attempts | 0 | ≥ 1 (quarantine) |
| Ideas → M1 conversion | 10–20% | <5% (too strict) or >30% (too loose) |

## 5. Legal & Attribution Boilerplate

Every IP draft produced by this loop **must** include:

> **AI Disclosure (per USCO 88 FR 16190, 2023):** Portions of this document were drafted with assistance from an AI system. The named human inventor(s)/author(s) reviewed, edited, and take full responsibility for the content. No AI system is claimed as inventor or author. See *Thaler v. Vidal*, 43 F.4th 1207 (Fed. Cir. 2022).

## 6. Prime-Directive Alignment

- **Phase 1 ($10k/mo):** loop produces 1–2 shipped M1s/month via Polar.sh funding + OSINT tool listings.
- **Phase 2 ($30k/mo):** 3–5 M1s/month, calibration Brier < 0.22.
- **Phase 3 ($100k/mo):** portfolio of graduated M1s → M2 (revenue), Brier < 0.20.
- **Phase 4 ($10M total):** IP portfolio (human-filed) becomes a defensible moat.

## 8. Change Control

Amendments to this WR require: (a) a PR from a human maintainer, (b) two CODEOWNER approvals, (c) explicit rationale for any change to §2 (Hard Constraints) or §3 Stage 7 (GATE). Agents may not propose amendments to §2 or Stage 7.
