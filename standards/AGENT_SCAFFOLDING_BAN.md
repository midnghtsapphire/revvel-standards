# Agent Scaffolding Ban

Generated AI tools (Lovable, Replit, Manus, Bolt, v0, Cursor, Copilot, Devin,
GitHub Copilot Workspace, Claude Code, etc.) routinely leave their fingerprints
in the code they produce: watermark footers, attribution strings, generic Vite
test scaffolding the user never asked for, default placeholder pages, generated
README sections, "Made with X" badges.

These are not acceptable in a sellable product. This standard lists the banned
artifacts and is enforced by `.github/workflows/agent-fingerprint-gate.yml` via
`scripts/agent-fingerprint-scan.js`.

## What gets blocked

### A. Attribution / "Made with" footers

These strings, anywhere in any file the PR touches, fail the gate:

- `Made with Lovable`, `Built on Lovable`, `Powered by Lovable`
- `Made with Replit`, `Built on Replit`, `Powered by Replit`
- `Made with Manus`, `Powered by Manus`
- `Made with Bolt`, `Powered by Bolt`, `bolt.new` (in user-facing copy)
- `Made with v0`, `Built with v0`, `v0.dev/` (in user-facing copy)
- `Generated by Claude`, `Generated by GPT`, `Generated by Cursor`
- `Co-Authored-By: Claude` in **user-facing files** (allowed in git history)

### B. Default scaffolding pages

The Vite/CRA/Next.js default app templates **must be replaced** before merge:

- `Welcome to Vite + React` / `Vite + React` / `Vite logo` (default `App.tsx`)
- `npm run dev` welcome text in any deployed page
- `getting-started.mdx` / `README-default.md` from a starter
- The `vite.svg` / `react.svg` default favicons (must be replaced with the product's actual logo)
- `count is 0` + `setCount((count) => count + 1)` counter (the CRA/Vite default)

### C. Unused test scaffolding

Generated test files that don't test the actual product, just the template:

- `src/App.test.tsx` that only checks "renders learn react link" or "renders Vite + React"
- `src/setupTests.ts` if no test in the repo actually uses it
- `__tests__/example.spec.ts` (generic placeholder names)
- `playwright/e2e/example.spec.ts`

### D. Unrequested README sections

When the user didn't ask for a README, the agent shouldn't generate boilerplate
like:

- "This project was bootstrapped with Create React App"
- "## Available Scripts"
- "## Learn More" with links to Vite/React docs
- "## Deploy on Vercel" with the Vercel badge

If the user wants a README they'll ask. Generic generated ones get blocked.

### E. Watermarked assets

Image / SVG / font assets that contain the generator's name in metadata or
visible text:

- SVGs with `<!-- Generated by Manus -->` / `<!-- Created with Lovable -->`
- PNGs / JPEGs with EXIF `Software: ...` matching banned generators _(TODO — not yet enforced; scanner is regex-text-only)_
- `logo.png` that's actually the Lovable/Replit/Bolt logo

## Allowed

Attribution **inside developer-facing docs** (anywhere under `docs/`, all
`standards/`, `CONTRIBUTING.md`) is fine — credit where due. The scanner
allowlists those paths. The rule is about what ships to users in product code.

Git commit messages may include `Co-Authored-By:` lines per the project's
existing convention.

## Exceptions

If a fingerprint is intentional (e.g., a tutorial product about how to build
with Lovable), add `agent-fingerprint:allow <reason>` to the PR body to suppress
the gate for that PR only.

## Per-tool profiles

See `docs/agents/<tool>/PROFILE.md` for tool-specific known fingerprints and
gotchas as we observe them in practice.

## Re-generating the rule list

Add new banned strings to `scripts/agent-fingerprint-scan.js` → `BANNED`.
The scanner is the source of truth; this doc explains the why.
