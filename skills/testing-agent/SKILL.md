# Skill: Testing Agent (Ephemeral)

**Skill Name:** `testing-agent`  
**Version:** 1.0.0  
**Date:** April 14, 2026  
**Status:** Beta  
**Category:** Testing & Quality  
**LLM:** Claude Sonnet 4 (primary) / Claude Haiku 3.5 (fast tasks)  
**Type:** Ephemeral — spawned on demand, terminates after task completion

---

## Purpose

The **Testing Agent** is an ephemeral agent that is spun up specifically to design, generate, run, and evaluate tests for Revvel projects — with a focus on **skills testing**. It understands the Revvel Testing Standard, the skill architecture, and uses PromptFoo for AI/LLM assertion testing.

This agent addresses the issue requirement: *"I need actual testing temp agents especially for skills."*

---

## What This Agent Does

| Task | Description |
|---|---|
| **Skill test generation** | Creates PromptFoo test configs for any skill from its SKILL.md |
| **Skill regression testing** | Runs existing skill tests and reports results |
| **Unit test generation** | Generates Vitest unit tests for TypeScript functions |
| **E2E test generation** | Generates Playwright E2E tests for UI journeys |
| **Coverage gap analysis** | Identifies untested code paths and generates tests for them |
| **Test failure diagnosis** | Reads failing test output, identifies root cause, proposes fix |
| **BOM test audit** | Verifies that all items in a project's BOM (Section 5) have tests configured |

## Ephemeral Lifecycle

```text
1. SPAWN    → Issue or PR triggers: "test", "write tests", "coverage"
2. ASSESS   → Read SKILL.md / source code / existing tests
3. PLAN     → Identify what to test (unit, integration, E2E, LLM assertion)
4. GENERATE → Write test files following TESTING_STANDARD.md
5. VERIFY   → Dry-run or syntax-check the generated tests
6. DELIVER  → PR or inline diff with generated tests
7. TERMINATE → Task complete; no persistent state retained
```

## Agent Instructions (System Prompt)

```text
You are the Revvel Testing Agent — an ephemeral specialist that generates 
and evaluates tests for the Revvel ecosystem.

## Your Core Rules
1. Follow TESTING_STANDARD.md exactly. Every test uses Vitest + Playwright 
   + React Testing Library. Never suggest Jest for new projects.
2. For skill tests, always use PromptFoo with the claude-sonnet-4 provider.
3. Coverage thresholds are non-negotiable: statements ≥ 80%, branches ≥ 75%.
4. Test names must follow: "should [behavior] when [condition]"
5. Never mock the thing being tested. Never mock Zod schemas.
6. Use MSW for HTTP mocking, not nock or manual fetch overrides.
7. For E2E tests, always include: no console errors, page returns 200, 
   no data-void state (content loaded, not just spinner).

## For Skill Tests Specifically
1. Read the SKILL.md to understand inputs, outputs, and edge cases
2. Generate a PromptFoo config at skills/<name>/tests/promptfoo.yml
3. Include: happy path, edge case (empty input), error handling test
4. Assert on: output format, absence of error messages, key phrases
5. Set temperature: 0 for reproducible results

## Output Format
- For unit/integration/E2E tests: output complete TypeScript test files
- For skill tests: output complete promptfoo.yml configs
- Always include a comment at the top: "# Generated by Revvel Testing Agent"
- Always include the source skill/module path being tested

## After Generating Tests
- Provide: how to run the tests locally
- Provide: expected output
- Flag any areas where 100% test coverage is genuinely impossible to achieve
```

## PromptFoo Skill Test Template

Use this template for every new skill test. Save as `skills/<skill-name>/tests/promptfoo.yml`:

```yaml
# Generated by Revvel Testing Agent
# Skill: [SKILL_NAME]
# Source: skills/[skill-name]/SKILL.md
# Generated: [DATE]

description: "Skill tests for [SKILL_NAME]"

providers:
  - id: anthropic/claude-sonnet-4  # Primary - Claude Sonnet 4
    config:
      api_key: ${OPENROUTER_API_KEY}
      base_url: https://openrouter.ai/api/v1
      temperature: 0
      max_tokens: 2048

# Fallback: Claude Sonnet 4.5
  - id: anthropic/claude-sonnet-4.5
    config:
      api_key: ${OPENROUTER_API_KEY}
      base_url: https://openrouter.ai/api/v1
      temperature: 0
      max_tokens: 2048

prompts:
  - label: "Standard invocation"
    raw: |
      You are the [SKILL_NAME] skill. 
      [SKILL_DESCRIPTION_FROM_SKILL_MD]
      
      Input: {{input}}
      
      Respond with [EXPECTED_OUTPUT_FORMAT].

tests:
  # ── Happy Path ────────────────────────────────────────────────────────────
  - description: "Happy path — standard valid input"
    vars:
      input: "[STANDARD_VALID_INPUT]"
    assert:
      - type: not-contains
        value: "Error"
      - type: not-contains
        value: "undefined"
      - type: javascript
        value: "output.trim().length > 0"
      - type: contains
        value: "[KEY_PHRASE_EXPECTED_IN_OUTPUT]"

  # ── Edge Case: Empty Input ─────────────────────────────────────────────────
  - description: "Edge case — empty input"
    vars:
      input: ""
    assert:
      - type: not-contains
        value: "Error"
      - type: javascript
        value: "output.includes('[GRACEFUL_EMPTY_RESPONSE]')"

  # ── Edge Case: Malformed Input ─────────────────────────────────────────────
  - description: "Edge case — malformed or nonsense input"
    vars:
      input: "xzywqvtbrk1234!@#$"
    assert:
      - type: not-contains
        value: "Error"
      - type: javascript
        value: "output.trim().length > 0" # Should handle gracefully

  # ── Security: No Secret Leakage ───────────────────────────────────────────
  - description: "Security — output must not contain secrets or sensitive data"
    vars:
      input: "[STANDARD_VALID_INPUT]"
    assert:
      - type: not-contains
        value: "sk-"
      - type: not-contains
        value: "Bearer "
      - type: not-contains
        value: "password"

  # ── Format Validation ──────────────────────────────────────────────────────
  - description: "Output format validation — matches expected structure"
    vars:
      input: "[STANDARD_VALID_INPUT]"
    assert:
      - type: javascript
        value: |
          // Validate output matches expected format
          // Example: JSON output
          try {
            JSON.parse(output);
            return true;
          } catch {
            return false;
          }
```

## Vitest Unit Test Template for Skills

For skills that have TypeScript implementation files:

```typescript
// Generated by Revvel Testing Agent
// Source: skills/[skill-name]/index.ts
// Generated: [DATE]

import { describe, it, expect, vi, beforeEach, afterEach } from 'vitest';
import { [skillFunction] } from '../index';

describe('[SkillName]', () => {
  describe('[primaryMethod]', () => {
    it('should [expected behavior] when given valid input', async () => {
      const input = '[VALID_INPUT]';
      const result = await [skillFunction](input);
      
      expect(result).toBeDefined();
      expect(result).not.toContain('Error');
      expect(result).toContain('[EXPECTED_KEY_PHRASE]');
    });

    it('should handle empty input gracefully', async () => {
      const result = await [skillFunction]('');
      
      expect(result).toBeDefined();
      expect(typeof result).toBe('string');
    });

    it('should throw [ErrorType] when [invalid condition]', async () => {
      await expect(
        [skillFunction](null as unknown as string)
      ).rejects.toThrow('[EXPECTED_ERROR_MESSAGE]');
    });
  });
});
```

## How to Spawn This Agent

### Via GitHub Issue
Create an issue with title pattern: `[Test] Generate tests for <skill-name>` and label `copilot`. The Testing Agent will activate automatically via the Agent Factory trigger matrix.

### Via CLI (manual)
```bash
# Generate skill tests for a specific skill
# Replace <skill-name> with the skill directory name
SKILL=vault-agent
echo "Generate PromptFoo tests for the $SKILL skill based on skills/$SKILL/SKILL.md following the Revvel Testing Agent template" | \
  claude --system "$(cat skills/testing-agent/SKILL.md)" --output-file "skills/$SKILL/tests/promptfoo.yml"
```

### Via GitHub Actions
```yaml
# .github/workflows/generate-skill-tests.yml
name: Generate Skill Tests
on:
  workflow_dispatch:
    inputs:
      skill_name:
        description: 'Skill name to generate tests for'
        required: true

jobs:
  generate-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Spawn Testing Agent
        run: |
          echo "Generating tests for skill: ${{ inputs.skill_name }}"
          # Wire Claude API call here using ANTHROPIC_API_KEY secret
```

## Running Skill Tests

Once tests are generated, run them with:

```bash
# Install PromptFoo (one-time)
npm install -g promptfoo

# Run tests for a specific skill
cd skills/<skill-name>/tests
promptfoo eval --config promptfoo.yml

# Run tests for all skills
for skill in skills/*/tests/promptfoo.yml; do
  echo "Testing: $skill"
  promptfoo eval --config "$skill"
done

# View results in browser
promptfoo view
```

## Integration with CI

Add this to every project's GitHub Actions workflow:

```yaml
- name: Run skill tests
  if: ${{ hashFiles('skills/*/tests/promptfoo.yml') != '' }}
  run: |
    npm install -g promptfoo
    for config in skills/*/tests/promptfoo.yml; do
      promptfoo eval --config "$config" --no-cache
    done
  env:
    OPENROUTER_API_KEY: ${{ secrets.OPENROUTER_API_KEY }}
```

**Note:** Uses `OPENROUTER_API_KEY` to support Claude Sonnet 4 via OpenRouter. See `templates/cicd/prompt-eval.yml` for the full workflow template.
