# Manus — Profile

Autonomous agent that runs in a sandbox VM with full shell, file, browser, and
SSH tools. Strong at deploy-and-verify loops (the SOP that lives at
`docs/MANUS_DEVELOPMENT_PIPELINE.md`).

## What it's actually good at

- End-to-end deploy + verify: build → scp/rsync → restart pm2 → curl-check.
- SSH-based ops on existing droplets.
- Reading PM2 / nginx logs and tracing live errors.

## What it tends to over-engineer

- Re-running entire build/deploy cycles when one-file edits would suffice.
- Adding its own scaffolding scripts to the repo (clean these up before
  merging).

## What it tends to hallucinate

- File paths inside its sandbox that don't exist on your droplet.
- Server state that no longer matches reality after manual changes.

## Fingerprints to scrub before shipping

- `Made with Manus` / `Powered by Manus` strings.
- `<!-- Generated by Manus -->` SVG/HTML comments.
- Scratch scripts in repo root (`plan.md`, `finish_clean.js`, `fix_boilerplate.js`,
  `update_wr.js`) — already enforced by `no-root-junk.yml`.

Gate: `scripts/agent-fingerprint-scan.js` (rule id: `manus-attr`).

## Prompt shapes that work

- "Use the SOP in `docs/MANUS_DEVELOPMENT_PIPELINE.md`. Verify with curl + UA
  before declaring done."
- "Don't add scratch scripts. Don't change PM2 config."

## Session capture

Manus session transcripts available via its UI; paste into
`docs/agents/manus/transcripts/<date>-<topic>.md` on session close.
