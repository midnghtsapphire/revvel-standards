# Claude — Profile

How Claude (Claude Code, web app, API) processes input so you can adapt your
prompts. Living doc — update as you observe more.

## Models you'd actually use

- **Opus 4.7 / 4.8** — heavy code, multi-step reasoning, audit work. Expensive
  per token.
- **Sonnet 4.6** — most agent surfaces wrap this; balanced.
- **Haiku 4.5** — cheap classifications, label sorts, light queries.
- **Fable 5** — fast / streaming preview lane.

## How it processes

- Extended-thinking trace is where the real reasoning lives. The UI hides it
  after the response posts. The JSONL transcript (`/root/.claude/projects/...`)
  keeps it. Capture this — it's the most useful data for tuning prompts.
- Defaults to asking clarifying questions when a request is even slightly
  ambiguous. Burns tokens. Counter with: "no questions, do the smallest
  defensible version."
- Defaults to "let me explain the architecture first" before doing. Counter with:
  "no architecture pitch — just produce the file."
- Tends to recap your message back at you before responding. Counter with:
  "don't echo me; respond only."
- Defaults to multi-phase plans. Counter with: "one iteration, full version."

## What it's actually good at

- Bash, YAML, regex edge cases (heredoc escaping, shell injection, command
  substitution).
- Cross-file refactors that follow an existing contract.
- Diagnosing audit-style problems across many workflows.
- Writing markdown that doesn't read as AI-generated.

## What it tends to over-engineer

- Architecture pitches when you wanted output.
- Phase 1/2/3 plans when you wanted the whole thing.
- "Want me to ...?" follow-up questions instead of acting.
- Verbose commit messages.
- Adding emojis when you didn't ask.

## What it tends to hallucinate

- Files it didn't create (cites paths that don't exist).
- Tool flags/options (especially less-common CLI tools).
- API endpoints (defaults to plausible-looking URLs that 404).
- Sometimes claims a commit SHA exists when it's about to be produced
  (related: marks something "✅ Resolved" referring to in-flight work that
  hasn't pushed yet).

## Token-economy gotchas

- Each "?" you write earns a long preamble before any work. Statements get
  faster, shorter responses than questions.
- Mid-task webhook noise (Vercel build comments, Ship Quality PASS, etc.)
  earns acknowledgment turns. Use slash-command rules to mute classes of these.
- Worktree/sandbox subagents multiply cost — only spawn when work is genuinely
  parallel.

## What works as prompt shape

- "Do X. No questions. Stop talking when done." — terse, action-only.
- "Receive only, no solving" (brain-dump mode) followed by "sort" — separates
  capture from triage.
- Concrete file paths + line numbers in the prompt — drops research overhead.
- "Use existing pattern: <path>" — prevents re-design.

## Fingerprints to watch

- `Generated by Claude` in user-facing files (allowed in dev docs only) — **enforced**.
- `Co-Authored-By: Claude` in user-facing files (allowed in git commit messages) — **enforced**.
- Emoji-heavy README sections unless explicitly asked — **not enforced today** (heuristic too noisy); rely on the standard + review.

## Session capture

`.claude/hooks/save-transcript.sh` lifts the raw JSONL to
`docs/agents/claude/transcripts/<date>-<topic>.md` on session end so the
thinking blocks survive.
