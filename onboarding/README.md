# Onboarding Guides

Plain-English guides for people joining the operation who are NOT expected to
code. Each guide is a self-contained job description with everything needed
to be productive in a browser.

| [MONTHLY_BUDGET_TEMPLATE.md](./MONTHLY_BUDGET_TEMPLATE.md) | Same as above | Copy-paste template for planning each month's subscription spending |

## Adding a new guide

Do NOT write an onboarding guide the way a technical doc is written. These
should be:

- Written second-person, "you", as if talking to a real person
- Explicit about GitHub browser workflow (edit-in-place, PRs, comments)
- Clear about what NOT to do
- Explicit about "when in doubt, comment don't act"
- No jargon; if a jargon word is unavoidable, define it inline

The audience for these guides is a smart human who has never used GitHub
professionally. Every instruction should be doable without leaving the
browser.
