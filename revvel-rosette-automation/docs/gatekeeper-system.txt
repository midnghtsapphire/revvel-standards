Gatekeeper System Overview
===========================

The Gatekeeper system provides automated secret provisioning and access control
across all MIDNGHTSAPPHIRE repositories.

Architecture
------------

                    ┌─────────────────┐
                    │  GitHub Actions │
                    │   (Trigger)     │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │   Gatekeeper    │
                    │   Automation    │
                    └────────┬────────┘
                             │
                ┌────────────┼────────────┐
                │            │            │
                ▼            ▼            ▼
           ┌────────┐  ┌─────────┐  ┌────────┐
           │ Doppler│  │  Vault  │  │ GitHub │
           │  API   │  │   API   │  │  API   │
           └────────┘  └─────────┘  └────────┘

Components
----------

1. gatekeeper-sync.sh (Main script)
   - Located in ../scripts/gatekeeper-sync.sh
   - Provisions GitHub Secrets from Doppler
   - Supports dry-run mode
   - JSON output for CI integration

2. src/gatekeeper.py (Python wrapper)
   - High-level automation API
   - Health checks
   - Auto-provisioning on issue labels

3. GitHub Actions Workflow
   - .github/workflows/credential-gatekeeper.yml
   - Triggers on: issue opened, labeled, PR opened
   - Watches labels: needs-secrets, wr:auto, wr:code

Workflow
--------

1. User opens issue or PR
2. GitHub Actions workflow triggered
3. Workflow calls gatekeeper-sync.sh
4. Script fetches secrets from Doppler
5. Script creates/updates GitHub Secrets
6. Success/failure reported as issue comment

Secret Naming Convention
------------------------

Secrets are named based on their purpose:

- API keys: {SERVICE}_API_KEY (e.g., OPENROUTER_API_KEY)
- Tokens: {SERVICE}_TOKEN (e.g., DOPPLER_TOKEN)
- Credentials: {SERVICE}_{TYPE} (e.g., DATABASE_URL)

Common Secrets
--------------

Core:
- OPENROUTER_API_KEY: AI model routing
- DOPPLER_TOKEN: Secret management
- GITHUB_TOKEN: GitHub API access

Services:
- TRELLO_API_KEY: Trello integration
- TRELLO_TOKEN: Trello auth token
- RESEND_API_KEY: Email service
- DIGITALOCEAN_API_TOKEN: Cloud infrastructure
- VERCEL_TOKEN: Deployment platform

Vault:
- VAULT_ADDR: HashiCorp Vault address
- VAULT_TOKEN: Vault authentication
- VAULT_NAMESPACE: Vault namespace

Security Features
-----------------

1. Just-in-time provisioning
   - Secrets created only when needed
   - Reduces attack surface

2. Automatic rotation
   - Credentials rotate every 90 days
   - Advance notification (14 days)

3. Audit logging
   - All secret access logged
   - Centralized audit trail

4. Least privilege
   - Per-repo secret scoping
   - No shared credentials across repos

Usage Examples
--------------

# Provision secrets for a repository
./scripts/gatekeeper.sh --repo midnghtsapphire/revvel-standards \
                        --secrets "OPENROUTER_API_KEY,DOPPLER_TOKEN"

# Dry run mode
DRY_RUN=1 ./scripts/gatekeeper.sh --repo owner/repo --secrets "KEY1,KEY2" --json

# Python API
python3 src/gatekeeper.py --provision --repo owner/repo --secrets "KEY1,KEY2"

# Health check
python3 src/gatekeeper.py --health-check

Troubleshooting
---------------

Issue: "Secret not found in Doppler"
Solution: Verify secret exists in Doppler project 'revvel-standards' config 'prd'

Issue: "GitHub API rate limit"
Solution: Wait for rate limit reset or use token with higher limits

Issue: "Permission denied"
Solution: Verify GITHUB_TOKEN has 'secrets' write permission

Monitoring
----------

# Check Gatekeeper status
./scripts/monitoring.sh

# View recent provisioning activity
grep "gatekeeper" logs/cronjob-*.log

# Check for failures
grep "ERROR" logs/cronjob-*.log | grep "gatekeeper"
